Understanding fetch() in JavaScript

Asynchronous network requests, Promises, and data handling

1. What is fetch()?

fetch() is a modern, built-in JavaScript browser API used to make HTTP requests (GET, POST, PUT, DELETE) across a network. It replaces older technologies like XMLHttpRequest (AJAX).

  • Asynchronous by nature: It runs in the background and does not freeze or block the browser UI while waiting for the server response.
  • Returns a Promise: Whenever you invoke fetch(url), it immediately returns a Promise representing an operation that will complete in the future.

2. Why does console.log(x) print a Promise?

Observation: In your initial code: 

var x = fetch('https://fakestoreapi.com/products');
console.log(x); // ➔ Promise { <state>: "pending" }

Because network requests take time to travel over the internet, JavaScript cannot give you the data synchronously on the very same line. Instead, fetch() immediately hands you an unresolved Promise object in the pending state.

3. How to Extract Data Correctly

To get the actual data from a fetch() call, you have two approaches:

Approach A: Using .then() Promise Chaining

A 2-step process: First get the HTTP response, then parse the body (e.g. .json() or .text()).

fetch('https://fakestoreapi.com/products')
  .then((response) => {
    // 1. Check if the response was successful (status 200-299)
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    // 2. Parse response stream as JSON (returns another Promise)
    return response.json();
  })
  .then((data) => {
    // 3. Access the actual parsed data here!
    console.log('Fetched Products via .then():', data);
  })
  .catch((error) => {
    // 4. Catch network errors or parsing failures
    console.error('Error fetching data:', error);
  });

Approach B: Using Modern async / await

Cleaner, synchronous-looking syntax for working with Promises:

async function getProducts() {
  try {
    const response = await fetch('https://fakestoreapi.com/products');
    
    if (!response.ok) {
      throw new Error(`HTTP error! Status: ${response.status}`);
    }

    const data = await response.json();
    console.log('Fetched Products via async/await:', data);
  } catch (error) {
    console.error('Fetch Error:', error);
  }
}

getProducts();

4. Key Points to Remember

  • Two-Step Asynchronous Flow: fetch() gives a Response object stream. You must call and await response.json(), response.text(), or response.blob() to read the payload.
  • HTTP Errors Don't Reject: fetch() does not reject on 404 or 500 HTTP status codes. It only rejects on network failures/offline states. Always check response.ok (boolean) or response.status.
